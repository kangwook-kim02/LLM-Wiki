# Skill: pr-review

## 입력

| 변수 | 설명 | 예시 |
|------|------|------|
| `$N` | PR 번호 | `3` |

## 절차

### Step 1 — PR 및 연결 이슈 파악

```bash
gh pr view $N --json title,body,baseRefName,headRefName,files,commits
gh pr diff $N
```

PR 본문에서 `closes #N` 또는 `fixes #N` 패턴을 찾아 연결된 이슈 번호를 추출한다.

```bash
gh issue view {이슈번호}
```

이슈의 **목표**, **작업 범위**, **완료 기준**을 파악한다.

### Step 2 — 의사결정 컨텍스트 파악

`docs/decision-log.md`를 읽어 이 PR과 관련된 라운드(아키텍처 결정, 방향 변경 등)를 확인한다.

### Step 3 — 리뷰 실행

변경된 파일 목록과 diff를 기반으로 아래 4개 관점에서 검토한다.

#### 관점 1: 완료 기준 충족 여부
이슈의 "완료 기준" 항목을 하나씩 대조한다.

#### 관점 2: CLAUDE.md 운영 규칙 준수
핵심 체크 항목:
- Wiki 읽기/쓰기에 내장 Read/Write 도구를 사용하지 않았는가? (MCP 도구만 사용)
- `raw/` 파일을 직접 수정하지 않았는가?
- 페이지 생성 후 `wiki_write("index", …)` 호출이 있는가?
- Wiki 작업 후 `wiki_write("log", …)` 호출이 있는가?
- 내부 링크가 `[[slug]]` 형식인가?
- YAML frontmatter가 포함되어 있는가?

#### 관점 3: 코드 품질
- 함수·변수명이 의도를 명확히 표현하는가?
- 불필요한 주석이나 dead code가 없는가?
- 에러 처리가 시스템 경계(외부 입력, MCP 응답)에서만 이루어지는가?

#### 관점 4: 의존성 및 범위
- 이슈 범위를 벗어난 변경이 없는가?
- 다른 이슈에서 다룰 내용을 미리 구현하지 않았는가?

### Step 4 — 리뷰 결과 보고

아래 형식으로 보고한다:

```
## PR #$N 리뷰 — {PR 제목}

### 완료 기준 체크
- [x] {항목 1}
- [x] {항목 2}
- [ ] {항목 3} ← 미충족: {이유}

### CLAUDE.md 규칙 준수
- [x] MCP 도구만 사용
- [x] index 업데이트
- [ ] {항목} ← 위반: {파일명:라인}

### 코드 품질
{발견된 문제 없으면 "이상 없음"}
{문제 있으면 파일명:라인 형식으로 지적}

### 범위 이탈
{없으면 "이상 없음"}
{있으면 구체적으로 서술}

---
### 종합 판정
✅ LGTM — 모든 항목 통과, 머지 가능
또는
⚠️ 수정 필요 — {핵심 수정 항목 1~3줄 요약}
```

---

## 원칙

- 칭찬보다 구체적인 지적을 우선한다 — "좋습니다" 같은 표현 최소화
- 파일명과 라인 번호를 반드시 명시한다 (`파일:라인`)
- 완료 기준 미충족 항목이 하나라도 있으면 LGTM을 주지 않는다
- CLAUDE.md 규칙 위반은 코드 품질 문제보다 높은 우선순위로 취급한다
- PR 머지는 사용자가 직접 판단한다 — 스킬은 머지를 실행하지 않는다
